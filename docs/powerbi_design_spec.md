# Power BI Executive Dashboard — Build Specification

## Environment Note (Read First)

**Power BI Desktop is not available in this project's development
environment** — it's a Windows GUI application, and this sandbox is a
headless Linux container with no network access to install or run it.
This mirrors the same practical constraint already documented for
PostgreSQL in Phase 4 (`docs/database_schema.md`).

To deliver something genuinely useful despite that constraint, this phase
produces **two things**:

1. **This specification** — a complete, ready-to-build Power BI plan (data
   model, DAX measures, page-by-page layout) that anyone with Power BI
   Desktop and this project's database can build in under an hour.
2. **`powerbi/executive_dashboard.html`** — a working, interactive
   executive dashboard built from the *exact same KPI definitions and
   underlying data* as a functional stand-in, so this phase has a real,
   usable deliverable rather than only a document. It is not a Power BI
   file and does not claim to be one — see its own header note.

Every number in both is grounded in `docs/kpi_framework.md` (Phase 10) and
`powerbi/dashboard_data.json` (generated by
`python/export_dashboard_data.py`), so there is nothing here that isn't
traceable back to the validated dataset.

## Data Model (Import into Power BI)

Import directly from `data/processed/ecommerce_analytics.db` (Power BI can
connect to SQLite via an ODBC driver, or the underlying CSVs in
`data/processed/*.csv` can be imported directly — either produces an
identical model). Load these 8 tables and let Power BI auto-detect the
relationships already enforced in Phase 4's schema:

| Table | Role |
|---|---|
| `fact_sales` | Fact table |
| `dim_customer`, `dim_store`, `dim_product`, `dim_subcategory`, `dim_category`, `dim_date` | Dimension tables (star schema, per `docs/database_schema.md`) |
| `customer_rfm.csv` (Phase 8 output) | Import separately, relate to `dim_customer` on `CustomerKey` |

Mark `dim_date` as a **Date Table** (Modeling → Mark as Date Table) using
`date_key`, so Power BI's built-in time intelligence functions work.

## DAX Measures

All measures below implement the definitions in `docs/kpi_framework.md`
exactly — no re-derivation, per that document's own rule.

```dax
Total Revenue = SUM(fact_sales[revenue_usd])

Total Orders = DISTINCTCOUNT(fact_sales[order_number])

Total Customers = DISTINCTCOUNT(fact_sales[customer_key])

Units Sold = SUM(fact_sales[quantity])

Average Order Value =
DIVIDE([Total Revenue], [Total Orders])

Revenue per Customer =
DIVIDE([Total Revenue], [Total Customers])

Historical CLV = [Revenue per Customer]
-- Same formula as Revenue per Customer; kept as a separate measure only
-- so it can be labeled "Historical CLV" on customer-focused pages without
-- renaming the underlying Revenue-per-Customer measure everywhere else.

Revenue YoY Growth % =
VAR CurrentYearRevenue = [Total Revenue]
VAR PriorYearRevenue =
    CALCULATE([Total Revenue], SAMEPERIODLASTYEAR(dim_date[date_key]))
RETURN
    DIVIDE(CurrentYearRevenue - PriorYearRevenue, PriorYearRevenue)

New Customers =
CALCULATE(
    DISTINCTCOUNT(fact_sales[customer_key]),
    FILTER(
        VALUES(fact_sales[customer_key]),
        CALCULATE(MIN(fact_sales[order_date])) IN VALUES(fact_sales[order_date])
    )
)
-- Simpler equivalent: precompute a "first order date" column on
-- dim_customer via Power Query (min(order_date) per CustomerKey) and
-- filter on Year(first_order_date) = selected year. This is what the
-- HTML dashboard does (see python/export_dashboard_data.py) and is the
-- recommended approach — the pure-DAX version above is more fragile.

Repeat Customers =
CALCULATE(
    DISTINCTCOUNT(fact_sales[customer_key]),
    FILTER(
        VALUES(fact_sales[customer_key]),
        CALCULATE(DISTINCTCOUNT(fact_sales[order_number])) >= 2
    )
)

Repeat Purchase Rate % =
DIVIDE([Repeat Customers], [Total Customers])
```

**Customer Retention (Cohort, Month-1)** is *not* a simple DAX measure — it
requires the cohort/period-number logic built in `python/cohort_analysis.py`
(Phase 9). Import `data/processed/cohort_retention_pct.csv` as its own
table and reference it directly rather than trying to reimplement cohort
logic in DAX; this avoids a second, potentially divergent implementation of
the same metric (see Phase 10's "Change Control" rule).

## Geography / Channel (per KPI Framework conventions)

* Default geography: `dim_customer[Country]` / `[State]`.
* Channel: `IF(dim_store[is_online] = 1, "Online", "In-Store")` — add as a
  calculated column on `dim_store`.

## Page-by-Page Layout

### Page 1 — Executive Overview

* **KPI cards (top row):** Total Revenue, Total Orders, Total Customers, Average Order Value, Revenue YoY Growth %, Repeat Purchase Rate %
* **Revenue trend:** line chart, `dim_date[date_key]` (by month) on axis, `[Total Revenue]` as value
* **Revenue by category:** bar chart, `dim_category[category_name]` × `[Total Revenue]`
* **Revenue by region:** map or bar chart, `dim_customer[Country]` × `[Total Revenue]`
* **Top products:** table, top 10 by `[Total Revenue]`
* **Customer segments:** donut chart, `customer_rfm[segment]` × count of customers
* **Filters (report-level slicers):** Year, Country, Category, Channel

### Page 2 — Sales Performance

* Monthly sales trend (line, with YoY comparison toggle)
* Category performance (bar, sortable by revenue or growth)
* Product performance (table with revenue, units, rank — matches `sql/05_sales_analytics.sql` `top_10_products_by_revenue`)
* Regional performance (bar/map)
* Revenue growth (YoY and MoM, matches `yearly_revenue_and_growth` / `monthly_revenue_and_growth` SQL)

### Page 3 — Customer Intelligence

* Customer segments (RFM) — bar chart, count and revenue % per segment
* New vs. returning customers by year (stacked/clustered bar, from `repeat_vs_onetime`)
* Customer revenue distribution (matches Phase 6's decile analysis)
* Customer order frequency (histogram, matches Phase 6 `purchase_frequency_distribution`)

### Page 4 — Retention

* **Repeat Purchase Rate** (headline card) — 61.18%
* **Cohort retention matrix** (matrix visual or heatmap custom visual), from `cohort_retention_pct.csv`
* Retention trend — Month-1 retention by cohort over time (line)
* Customer segment distribution — repeated from Page 3, filtered to At Risk / Can't Lose Them / Lost for a retention-focused view

**Both retention metrics must appear with the labels from
`docs/kpi_framework.md`** ("Repeat Purchase Rate" vs. "Customer Retention
(Cohort, Month-1)") — never just "Retention" unlabeled, to avoid the
61.18%-vs-2.84% inconsistency flagged in Phase 10.

## Required Elements (per Phase 11 brief)

* **Filters:** Year, Country, Category, Channel slicers on every page (Power BI syncs slicers across pages via "Sync Slicers" pane)
* **Drill-downs:** enable drill-down on the category → subcategory → product hierarchy for the category bar chart; enable drill-down on `dim_date` (year → quarter → month) for the trend line
* **Tooltips:** enable report page tooltips showing revenue, orders, and AOV on hover for the revenue trend chart
* **Consistent KPI definitions:** every measure above matches `docs/kpi_framework.md` word-for-word
* **Clear business titles:** e.g. "Monthly Revenue Trend", not "Sum of revenue_usd by order_date"
